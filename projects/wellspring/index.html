01Wellspring — Open Amenity Network

Every van life shower app is either paywalled, proprietary, or both. iOverlander went $99/year on community-contributed data. The OSM tagging schema already supports showers, bathhouses, and fitness centres. Nobody's built the bridge.

Wellspring is a lightweight PWA that queries OpenStreetMap's Overpass API for shower and bathing facilities, layers on van-life-specific community metadata, and feeds objective data back to OSM through proper contribution channels. Free. Open-source. No subscription. No investor exit strategy.

What It Queries

OSM Tag Coverage
amenity=showerStandalone public showers — beach, truck stop, municipal
amenity=public_bathBathhouses, onsen, hammam, thermal baths, saunas
leisure=fitness_centreGyms — filtered by shower=yes and opening_hours=24/7
amenity=fuelTruck stops — filtered by shower=yes (Pilot, Love's, Flying J)
tourism=camp_siteCampgrounds — filtered by shower=yes
leisure=swimming_poolPublic pools with changing facilities

What OSM Can't Store (Wellspring's Layer)

OSM accepts objective, verifiable facts. Wellspring adds the subjective, van-life-specific metadata that the community actually needs but OSM's data model won't accept:

Facility Metadata
water_pressure1–5 rating, community avg
towel_policyprovided / byob / rental
access_methodkeycode / staffed / coin-op / fob
time_limitminutes, or unlimited
cleanliness1–5 rating, community avg
privacy_levelstall / curtain / open
Community Data
van_parkingnearby / onsite / hostile
overnight_okboolean + notes
last_verifiedISO date, contributor ID
photosCC-BY-SA licensed uploads
cost_actualUSD amount, last confirmed
reviewsFree text, ODbL-licensed

Architecture

stack // Frontend PWA (Vanilla JS + Leaflet) → installable, offline-capable Tiles: OpenStreetMap / OpenTopoMap (switchable) Search: Overpass API (live) + local IndexedDB cache // Backend (minimal) Hetzner VPS (alongside existing ARX infra) SQLite → community reviews, metadata, photos API: FastAPI or Hono (lightweight, single binary) // Data flow OSM Overpass → objective facility data (location, hours, tags) Wellspring DB → subjective community data (reviews, ratings) Contribution pipeline → verified objective data pushed back to OSM
Key Differentiator

Every competitor extracts from the commons and paywalls it. Wellspring is the reverse: build a focused tool, let the community enrich it, and export the objective data back to OSM so everyone benefits — including Garmin users, OsmAnd users, and any future tool built on open data.

Custom POI Layer — Amenities

Garmin supports custom POI files (.gpi) that overlay icons on the map. We generate these from an Overpass API query targeting showers, public baths, and rec centers in the target region, then convert to Garmin's POI format using gpsbabel.

overpass query → gpx → gpi # Query OSM for shower/bath amenities in Utah + nearby states [out:json][timeout:60]; area[name="Utah"]->.ut; area[name="Nevada"]->.nv; area[name="Arizona"]->.az; area[name="California"]->.ca; ( nwr[amenity=shower](area.ut)(area.nv)(area.az)(area.ca); nwr[amenity=public_bath](area.ut)(area.nv)(area.az)(area.ca); nwr[leisure=fitness_centre][shower=yes](area.ut)(area.nv)(area.az)(area.ca); nwr[amenity=fuel][shower=yes](area.ut)(area.nv)(area.az)(area.ca); ); out center; # Convert JSON → GPX → Garmin .gpi python3 overpass_to_gpx.py output.json > amenities.gpx gpsbabel -i gpx -f amenities.gpx -o garmin_gpi,bitmap=shower.bmp \ -F /Volumes/GARMIN_SD/Garmin/POI/showers.gpi

03OSM Mapping Party — St. George Pilot

You can't legally scrape Google Business Profiles into OSM. But you can organize volunteers to ground-truth amenities in person, properly tag them, and enrich the open map for everyone. This is how open data actually gets built.

Why Google → OSM Scraping Is Off The Table

Google's Terms of Service explicitly prohibit scraping, caching, or redistribution of their data. OSM's ODbL license requires all contributed data to come from license-compatible sources. The OSM community actively reverts bulk imports traced to Google data — they've killed entire datasets over this. Even indirect contamination (using Google to "confirm" data you then add) is a gray area the community polices.

But the need is real: OSM's business and amenity data in southern Utah is sparse. Google has it, OSM doesn't. The legal path is ground-truthing: go there, confirm it exists, tag it yourself from direct observation.

The StreetComplete Pipeline

StreetComplete is an open-source Android app (F-Droid available) that gamifies OSM contributions. It presents simple questions about nearby features as you walk: "Does this gym have showers?" "What are the opening hours?" "Is this wheelchair accessible?" No editing knowledge needed. Answers go directly to OSM.

App Stack for Mappers
StreetCompleteQuestion-based OSM editing (F-Droid). Primary tool for non-technical volunteers.
VespucciFull-featured OSM editor for Android. For adding new nodes with complete tagging.
OsmAndNavigation + OSM notes. Mark locations for later editing.
JOSMDesktop editor for bulk post-processing after field collection.

Switchpoint Integration

Invite Switchpoint residents and case workers to participate in mapping parties. The dual benefit: residents learn their city's resources by physically visiting them, and their on-the-ground knowledge enriches the map. Switchpoint staff can identify facilities their clients actually use that aren't yet in OSM — laundromats, food pantries, water fill stations, free wifi spots.

This creates a feedback loop: the Garmin kits (Tab 2) get better because the underlying OSM data gets richer from the mapping parties, and the Wellspring PWA (Tab 1) automatically surfaces the new data through Overpass queries.

The Actual Alternative to Scraping

Instead of illegally copying Google's database, you build a community that creates better data — verified in person, tagged with detail Google doesn't capture (shower=yes, fee amount, actual hours), and licensed for anyone to use. The data starts local in St. George, then the model replicates to Redding, then anywhere ARX has a presence.

Philosophy

This isn't a product. It's infrastructure. Every piece — the data, the code, the hardware spec, the mapping toolkit — is designed to outlive any single maintainer. ODbL means the data can't be re-enclosed. AGPL means the code can't be proprietarized. CC-BY-SA means the docs propagate freely. The iOverlander pattern (build on community goodwill, sell to Hipcamp, paywall everything) is structurally impossible here.
